    Compile the C++ wrappers as UTF-8 instead of warning C4819
    
    The QuantLib headers are UTF-8 without a BOM (author names in the licence
    headers, mathematical symbols in the documentation), so MSVC warns C4819
    for every translation unit that includes them unless the system code page
    happens to be UTF-8.  QuantLib itself now passes /utf-8 rather than
    suppressing the warning (lballabio/QuantLib#2803); do the same in the two
    wrapper builds that use MSVC, the C# property sheet and Python's setup.py.
    
    The toolsets below v141 go away with it.  The wrapper is built as C++17
    (LanguageStandard in cpp/QuantLibWrapper.vcxproj), which VS2015 and earlier
    cannot do, so those conditions were already dead; /utf-8 needs VS2015
    Update 2 in any case.  v145 is added to match QuantLib's own QuantLib.props.
